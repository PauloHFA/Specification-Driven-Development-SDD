## 2. Logic Chain

1. **Root Cause Analysis (Baseline State)**:
   - When real specifications were generated in the root repository `.spec/`, `resolveSpecDir` unconditionally appended `path.resolve(process.cwd(), '.spec')` to the candidates array regardless of whether the caller requested a custom non-existent directory or specified `fallbackToExamples: false`.
   - Consequently, negative test cases asserting `resolveSpecDir(...) === null` or asserting fallback to synthetic data accidentally resolved to the host repository's `.spec/`.
   - Simultaneously, Test 248 executed against `process.cwd()` without fixture isolation, encountering the 4-story host `.spec/` instead of triggering example fallback (2 stories).

2. **Remediation Mechanism Validation**:
   - The implemented solution partitions path resolution into Explicit vs Default modes.
   - For an explicit directory path that does not exist on disk:
     - If `fallbackToExamples === false`, candidate resolution terminates immediately returning `null`.
     - If `fallbackToExamples !== false`, it only permits resolving reference examples if the requested path was the standard `.spec` identifier (`.spec`, `./.spec`, `.//.spec`). Any custom non-existent directory (e.g. `'non_existent_folder_xyz'`) returns `null`.
   - In `loadSDDGraph`, a `null` resolved path correctly branches to `buildSyntheticFallback()` (when `fallbackToSynthetic !== false`), or throws `Specification directory not found` (when `fallbackToSynthetic === false`).
   - For Test 248, wrapping the test in `fs.mkdtempSync` ensures an isolated environment without a host `.spec/`, deterministically verifying example fallback.

3. **Integrity and Adversarial Review**:
   - **No Hardcoded Test Outputs**: The code contains no special-case string matching for test IDs or fake paths (`missing_dir_12345`, `non_existent_folder_xyz`). All checks are generic filesystem inspections using `existsSync` and `statSync().isDirectory()`.
   - **No Dummy/Facade Implementations**: `resolveExamplesDir` locates real physical directories on disk. Real SDD specs are parsed with full entity trees (US, AC, T, principles, assumptions, questions, and files).
   - **No Verification Shortcuts**: Tests run against real in-memory data and real filesystem nodes. Cleanup is guaranteed via `try ... finally`.
